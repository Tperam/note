## 简介

内网穿透有多个别称，P2P、P2P打洞、内网直连。

这些最原始的需求其实就是，我当前有两台内网电脑（不在同一局域网内），同时我希望他们能互相访问。

在这种时候，我们有几种解决方法。

1. 转发模式（通过拥有公网IP的服务器转发两个客户端之间的通信）
   - 该方式是需要你有一个公网服务器IP
   - 同时，你传输的宽带速率通常会被你服务器的速率所限制（服务器带宽极贵，特别是中国运营商），同时在某些极端情况下，延迟也会略高。
2. P2P内网穿透模式（两台机子通过某种方式成功实现互联）
   - 该方式也是需要你有一个公网服务器IP
   - 同时，该方式要求了一定的NAT类型。
   - 其相比于转发模式的优点在于，如果打洞成功，在带宽上仅受限与自己的上传下载网速。

### NAT介绍

首先，想要理解NAT，我们需要先知道一个client到server的链接是怎么建立起来的。

从我们当前简单内网穿透的程度来说，内容不多，中途仅涉及几个知识点：五元组，局域网，NAT设备。

#### 五元组

五元组是用于保存客户端与服务端的一个链接的记录，也可以叫做socket（个人感觉可以这么叫）。五元组中包含如下几个数据：

- src.ip
- src.port
- dst.ip
- dst.port
- 协议

client在与服务器建立链接时，就会生成一个五元组，其中就保存了上面的信息。例如，我们通过浏览器访问某个网站时，DNS解析域名得到`dst.ip`，https 就是使用 443端口，http 使用80端口，这里我们也就得到了`dst.port`。

在建立连接时，本机会根据`dst.ip`与`dst.port`，尝试匹配具体的路由策略（`ip route `/`iptables` 等路由策略）或浏览器自设定的路由策略，来决定`src.ip`，并随机生成一个端口用于`src.port`。同时市面上浏览器默认使用tcp协议。

经过上述例子，我们在访问一个网站时就能获得到一个五元组信息。

#### 局域网

局域网就是局域网（或叫内网），其能访问外网的原因是路由器设备做了一层NAT，将内部的端口转为了一个外部的端口。

根据上面介绍的五元组。

其实本地保存的五元组如下：

| key      | 值           | 介绍                                                         |
| -------- | ------------ | ------------------------------------------------------------ |
| src.ip   | 192.168.1.40 | 源地址，通常就是我们主机的IP（我只有一个网卡，所以路由策略将会获取到该网卡的内网IP） |
| src.port | 38774        | random 端口，具体随机范围忘记了，但应该是这个开头            |
| dst.ip   | 39.156.66.10 | 百度的具体IP（不同地方将回访问到不同的IP）                   |
| dst.port | 443          | https                                                        |
| 协议     | tcp          |                                                              |

假设，我们直接将当前五元组发送给百度的服务器，那百度知道需要回给谁吗？百度将会直接把请求回到他的内网一个IP为192.168.1.40的机器上。

所以，其实我们的路由器上层是做了一层NAT的，这层NAT将内网IP转变为了公网IP。

```shell
iptables -A FORWARD -o brlan -j ACCEPT
iptables -A FORWARD -i brlan -j ACCEPT
iptables -t nat -A POSTROUTING -s 192.168.1.0/24 ! -o brlan -j MASQUERADE
```

在STUN中定义的NAT类型如下：

| NAT 类型                 |              | 通常 |
| ------------------------ | ------------ | ---- |
| Full Cone                | 完全锥型     | NAT1 |
| Restricted Cone NAT      | 限制锥型     | NAT2 |
| Port Restricted Cone NAT | 端口限制锥型 | NAT3 |
| Symmetric NAT            | 对称NAT锥型  | NAT4 |

判断一个机器的STUN通常需要多个STUN服务器来确认机器STUN。





##### Full Cone (NAT 1)

建立过程（src为内网服务器）

1. 内网中随机生成一个端口，并使用该IP对外访问（192.168.1.40:38774）
2. 内网请求包到NAT层
3. NAT将创建一个映射记录（1.1.1.1:40048）
4. 将五元组信息的内网ip与port改为对应的映射记录。
5. 发包



回包时（src为云服务器）

1. 端口号 40048 收到一条消息
2. 获取NAT映射
3. 将请求转到内网192.168.1.40:38774端口上





##### Restricted Cone NAT（NAT 2）

也称为**地址受限锥型**

建立过程（src为内网服务器）

1. 内网中随机生成一个端口，并使用该IP对外访问（192.168.1.40:38774）
2. 内网请求包到NAT层
3. 记录dst.ip
4. NAT将创建一个映射记录（1.1.1.1:40048）
5. 将五元组信息的内网ip与port改为对应的映射记录。
6. 发包



回包时（src为云服务器）

1. 端口号 40048 收到一条消息
2. 判断src.ip是否被访问过
   - 如果没被访问过，则拒绝访问。
3. 获取NAT映射
4. 将请求转到内网192.168.1.40:38774端口上



##### Port Restricted Cone NAT（NAT 3）

也称为**端口受限锥型**

建立过程（src为内网服务器）

1. 内网中随机生成一个端口，并使用该IP对外访问（192.168.1.40:38774）
2. 内网请求包到NAT层
3. 记录dst.ip+dst.port
4. NAT将创建一个映射记录（1.1.1.1:40048）
5. 将五元组信息的内网ip与port改为对应的映射记录。
6. 发包



回包时（src为云服务器）

1. 端口号 40048 收到一条消息
2. 判断src.ip与src.port是否被访问过
   - 如果没被访问过，则拒绝访问。
3. 获取NAT映射
4. 将请求转到内网192.168.1.40:38774端口上



##### Symmetric NAT（NAT 4）

建立过程（src为内网服务器）

1. 内网中随机生成一个端口，并使用该IP对外访问（192.168.1.40:38774）
2. 内网请求包到NAT层
3. NAT判断dst.ip与dst.port信息，选定出口ip：port（40048）。
   - 在不同的IP下，可能为不同的端口。
4. NAT将创建一个映射记录（1.1.1.1:40048）
5. 将五元组信息的内网ip与port改为对应的映射记录。
6. 发包



回包时（src为云服务器）

1. 端口号 40048 收到一条消息
2. 判断src.ip根据规则是否能访问当前port
   - 不同IP下，访问的映射端口可能不同，甚至src.ip都不同。
     - 可能运营商基于安全考虑
     - 也有可能基于其他考虑
       - 例如：单个NAT设备处理的请求处理不过来了，按省份或大区划分（提高负载），广东省将走其他的NAT设备（IP）。
3. 获取NAT映射
4. 将请求转到内网192.168.1.40:38774端口上

#### 方式1（可能只是设想）

其实在上文的连接中也有提到，但对于我个人还没有理解透彻，看他的结论感觉还是缺点理解。所以此处基于自己的理解尝试写简单理论（当前理解未经实验，仅是曾探讨过的可能性）

背景：

- 我们是使用P2P
- 有以下关键词
  - c1（client1）
  - c2（client2）
  - s(server），定义为拥有公网IP的服务器。
  - ft（五元组、five-tuple）
  - socket（链接）

流程

1. c1 与 s 建立连接，此时我们可以得到以下信息
   - c1:ft，s:ft（此命名为 sft1）
2. c2 与 s 建立连接，此时我们也可以得到如下信息
   - c2:ft，s:ft（此命名为 sft2）
3. 此时我们使用s，往c1发送 sft2，往c2发送 sft1
4. 此时双端都得到了五元组信息。
5. c1根据 sft2 捏造出一个socket，往c2发送数据包
   - 其中src为s的ip，src.port为s的port，dst为c2的ip，dst.port为c2的port
   - 直接使用该socket进行发包（此实现理论基于上层Nat仅做转发，不对ft的src进行检查。能够绕过检测
6. c2同理，根据sft1捏造出socket，往c1发送数据包。
7. 如上述连通，则互联成功。

非激活：在60s内无通信（可能是NAT认为当前链接超时，将其删掉了）



我们有几种办法来处理上述情况（端口变动问题）：

1. 暴力遍历，找到对应的ip range 范围，从最小比例到最大（但速度也得快，因为非激活端口在一定时间后将会变换）
2. 与公网服务器建立连接，公网服务器获取到ip:port映射信息后，立刻关闭连接，让内网B在一分钟内，连接该ip:port，同时保活，使其能一直占用工作。

通过上述方式，我们就可以使内网服务器暴露，此时，就可以愉快的访问资源了！

经实验，暴力遍历端口失败，在另一台内网服务器中，暴力遍历30000-50000端口后被运营商抛弃。（后续使用已经打通端口也失败）

   ```go
   package main
   
   import (
       "fmt"
       "net"
       "time"
   )
   
   func main() {
       udpAddr, err := net.ResolveUDPAddr("udp", "0.0.0.0:12345")
       if err != nil {
           fmt.Println("Error: ", err)
       }
   
       conn, err := net.ListenUDP("udp", udpAddr)
       if err != nil {
           fmt.Println("Error: ", err)
       }
   
       // Use the same UDP connection to read and write
       go func() {
           buf := make([]byte, 1024)
           for {
               n, addr, err := conn.ReadFromUDP(buf)
               if err != nil {
                   fmt.Println("Error: ", err)
               }
               fmt.Printf("Received %s from %s\n", string(buf[0:n]), addr)
           }
       }()
   
       remoteAddr, err := net.ResolveUDPAddr("udp", "remote.server:12345") // Replace with your remote address
       if err != nil {
           fmt.Println("Error: ", err)
       }
       for {
           _, err = conn.WriteToUDP([]byte("Hello"), remoteAddr) // 一直打印，使其不掉。
           if err != nil {
               fmt.Println("Error: ", err)
           }
           time.Sleep(time.Second)
       }
   }
   ```
